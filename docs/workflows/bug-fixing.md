# Workflow: Bug Fixing

This document outlines the engineering process for identifying, isolating, and fixing bugs in the application.

---

## 1. Branch Naming

* **Standard Bugfix:** Created off `dev` for bugs found during development or testing cycles:
  `bugfix/issue-description` or `bugfix/issue-id`
* **Hotfix:** Created directly off `main` or a release tag if a critical issue is discovered in production, then merged back to both `main` and `dev`:
  `hotfix/issue-description`

---

## 2. Debugging and Isolation Protocol

1. **Reproduction:** Write down exact reproduction steps. Review diagnostic reports generated by `IDiagnosticService` (saved in logs or output viewports).
2. **Isolate Layer:** Determine if the issue is:
   * **Domain Layer:** Point-in-polygon algorithm bug, unit conversion formula mistake.
   * **Application Layer:** GA optimization convergence or fitness weight tuning logic issues.
   * **Infrastructure Layer:** EF Core mapping, SQLite connection locks, xBIM geometry calculation failures.
   * **UI Layer:** Binding mismatch, thread access exceptions (modifying UI models from background threads).

---

## 3. Write a Regression Test

To ensure the bug does not reappear (regression), write a unit test that fails before you apply the fix:
* Open `CraneOptimizer.Application.Tests` and locate the relevant test class (or create a new one).
* Write a test simulating the exact scenario that caused the bug.
* Assert that the correct behavior is outputted (the test should fail at this stage).

---

## 4. Implement the Fix & Validate

* Implement the code changes to resolve the bug.
* Run the regression test. It should now pass.
* Run the entire unit test suite locally to verify that no other modules were broken.
* Submit a PR with a commit prefix `fix: ...`. Provide reproduction steps and test results in the description.
